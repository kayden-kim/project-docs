# UX 문구 점검

애플리케이션 전체의 UX 문구를 점검한다.

## 프로젝트 기준과의 관계

- 문구의 판단 기준은 `anti-ai-slop` 스킬의 「2. UX 라이팅과 마이크로카피」와 「5. 한국어 현지화」를 함께 따른다. 프로젝트에 UI 문구 규칙이 있으면 그 규칙이 우선한다. 규칙의 위치는 `DESIGN.md`의 "UI 문구 규칙" 항목에서 찾는다.
- 용어는 프로젝트 용어집(`GLOSSARY.md`)이 있으면 그 이름을 따른다.
- 채택된 스펙이 정한 문구(예: 오류 문구)는 소스에서 바로 바꾸지 않는다. 변경안을 제시하고, 스펙이 바뀐 뒤 소스에 반영한다.
- 바꾼 문구를 확인하는 테스트가 있으면 새 문구에 맞춰 고치고 실행한다.

## 점검 범위

사용자에게 보이는 모든 문자열을 검토한다. 제목, 부제목, 내비게이션 레이블, 버튼, 툴팁, 플레이스홀더, 대화상자, 알림, 빈 상태, 오류 메시지를 포함한다.

AI가 쓴 듯한 문구 패턴을 없앤다.

## 문구마다 확인할 질문

- 사용자에게 이 정보가 정말 필요한가?
- 이미 보이는 내용을 반복하는가?
- 제품 UI가 아니라 광고처럼 들리는가?
- 더 자연스럽고 간결하게 표현할 수 있는가?
- 전문 UX 라이터라면 이 문구를 넣겠는가?

## 고치는 방법

- 불필요한 문구는 고쳐 쓰지 말고 지운다.
- 추상적인 마케팅 표현은 구체적이고 작업 중심적인 표현으로 바꾼다.
- 익숙한 단어, 일관된 용어, 대상 언어에 맞는 자연스러운 표현을 쓴다.
- 지운 문구를 메우려고 새 설명 문구를 추가하지 않는다.
- 필요한 경고, 접근성 레이블, 법적 정보, 맥락상 필요한 안내는 유지한다.

## 유지할 것과 반영 위치

- 애플리케이션의 기능, 시각 정체성, 비즈니스 로직을 유지한다.
- 레이아웃은 바뀐 문구를 수용하는 데 필요한 곳만 조정한다.
- 변경은 관련 소스 파일에 직접 적용한다.
