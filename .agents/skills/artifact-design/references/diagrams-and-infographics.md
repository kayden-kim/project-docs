# 도표·도식 레퍼런스

## 선택 기준

[스킬의 도식과 그림 규칙](../SKILL.md#도식과-그림)을 따른다. 그림은 문단에 대한 답이다. 빈 공간을 채우는 용도가 아니다.

아래 표에서 장면의 질문에 맞는 형식을 고른다. 한 문서의 모든 장면을 노드와 화살표 도식으로 그리지 않는다. 질문이 바뀌면 형식도 바꾼다. 표에 없는 형식도 질문에 더 잘 답하면 쓸 수 있다.

| 독자의 질문 | 시각 형식 | 글과의 위치 |
| --- | --- | --- |
| 전체에 어떤 역할이 있는가? | 넓은 개념도·전경 | 리드 아래 |
| 한 부분 안에는 무엇이 있는가? | 단면도·분해도·확대 렌즈·작은 삽화 | 문단의 여백 또는 아래 |
| 경로와 분기는 어디에 있는가? | `flowchart`식 노드·방향 화살표·조건 분기 | 개요 또는 분기 설명 옆 |
| 참여자 간 요청·응답 순서는? | `sequenceDiagram`식 swimlane과 메시지 화살표 | 참여자와 주고받는 문단 사이 |
| 상태는 어떻게 바뀌는가? | `stateDiagram-v2`식 상태와 이름 붙은 전이 | 상태 설명 가까이 |
| 무엇이 먼저 처리되고 무엇을 기다리는가? | 대기열·버퍼의 칸 그림, 처리 위치 표시 | 문단 옆 |
| 시간에 따라 무엇이 일어났는가? | 타임라인·간트·이벤트 띠 | 경과를 설명하는 문단 위아래 |
| 무엇이 무엇 아래에 속하는가? | 트리·들여쓴 목록·트리맵 | 구조 설명 옆 |
| 양이 어디서 어디로 얼마나 흐르는가? | 굵기가 양을 뜻하는 흐름도(Sankey) | 흐름을 설명하는 문단 다음 |
| 전체가 어떤 부분으로 나뉘는가? | 누적 막대·단위 도형(작은 도형 하나가 일정한 양) | 비율을 해석하는 문단 가까이 |
| 두 기준에서 항목은 어디에 놓이는가? | 2×2 매트릭스·산점도·히트맵 | 비교 문단과 함께 |
| 같은 구조를 조건별로 비교하려면? | 같은 축·크기의 작은 그림을 나란히 놓는 작은 배수(small multiples) | 비교 문단 아래 |
| 실제 공간이나 배치는 어떤가? | 평면도·지도·랙·화면 구획 | 배치를 설명하는 문단 옆 |
| 두 개념은 어떻게 다른가? | 대비되는 세로형 포스터·나란한 비교 도식 | 비교 문단과 함께 |
| 실제 수치가 얼마나 다른가? | 단위·기준·출처가 있는 표 또는 차트 | 해석 문단 가까이 |
| 이 코드는 무엇을 하는가? | 주석을 단 코드 조각·호출 트리 | 해당 설명 문단 옆 |

독자가 직접 바꿔 보며 확인해야 하는 질문이면 [인터랙션 레퍼런스](interactive-patterns.md)에서 조작 방식을 함께 고른다.

## Mermaid 같은 도식 문법

- 경로·순서·상태 변화가 질문인 장면에서는 흐름도, sequence, state 도식을 주요 설명 수단으로 쓴다. 각 노드에는 짧은 이름을 쓰고, 화살표에는 메시지·조건·결과를 붙인다. 양·비율·계층·공간이 질문인 장면은 위 표의 다른 형식을 쓴다.
- 넓은 개요도와 문단 사이의 작은 세부 도식을 함께 쓸 수 있다. 같은 흐름을 크기만 바꿔 반복하지 않는다.
- HTML 결과 환경이 Mermaid를 실제로 렌더링하지 않으면 원시 Mermaid 코드를 남기지 않는다. 단일 HTML은 의미 있는 인라인 SVG나 HTML로 같은 문법을 표현하고 외부 Mermaid 런타임을 불러오지 않는다.


## 서로 다른 크기의 그림

한 문서에는 전체를 보여주는 큰 그림, 부분의 구조를 보여주는 중간 그림, 시간이나 조작에 따른 변화를 보여주는 그림이 섞인다. 같은 그림을 크기만 바꿔 반복하지 않는다.

[템플릿](../assets/editorial-template.html)의 세 그림은 이 역할 분담의 한 예시다. 장면의 내용과 형식은 위 표에서 새로 고른다.

- `.cover-art`: 생성, 대기, 기록의 역할을 풍경처럼 배치한다. 시간 순서를 재생하지 않는다.
- `.gallery`: 대기열의 전체와 처리·기록의 세부를 서로 다른 크기의 SVG로 묶는다. 각 그림에 독립된 캡션이 있다.
- `.mechanism`: 같은 요청이 어떤 상태를 거쳐 응답되는지 보여준다. 노드, 방향과 현재 단계를 라벨로 표시한다.

## 사진과 삽화

실제 자료가 있으면 큰 장면, 세부 확대, 관련 사례를 조합한다. 파일을 내장할 때 출처와 사용 조건을 확인한다. 사진이 없으면 내용을 설명하는 벡터 도식을 만든다. 의미 없는 색 블록을 사진 자리라고 부르지 않는다.

설명에 기여하지 않는 배경 삽화·선화·잘라낸 실루엣은 넣지 않는다. 의미가 있는 SVG에는 `role="img"`, `title`과 `desc`를 연결한다.

## 선과 상태의 뜻

- 관계선은 연결의 뜻을, 화살표는 동작 방향을 나타낸다. 두 가지를 구분한다.
- 현재 단계는 강조색과 텍스트로 표시한다. 이미 지난 단계와 아직 오지 않은 단계도 라벨로 구분한다.
- 요청과 응답은 라벨로 구분한다. 색상만으로 방향이나 성공 여부를 설명하지 않는다.
- 기록되지 않은 요청에 성공 응답을 표시하지 않는다. 오류를 설명할 때는 성공 경로와 다른 결과를 적는다.
- 이동 속도를 실제 처리 시간처럼 보이게 하지 않는다. 설명용 모형이라는 점을 캡션에 적는다.

## 바탕과 팔레트

SVG의 `fill`·`stroke`에는 `var(--ink)`, `var(--accent)`, `var(--rule)`, `var(--paper)` 같은 템플릿 토큰을 쓴다. 그림을 위한 별도 고정 팔레트를 만들지 않는다. 문서 바탕·색상 구간·어두운 스타일에서도 라벨이 읽히는지 확인한다.

모든 그림을 독립된 박스로 가두지 않는다. 정보 관계와 동작 방향을 표현하는 선·화살표만 쓴다. 무장식 기본을 유지하고, 선 굵기는 역할과 가독성에 맞춘다.

## 모바일과 검증

- 의미가 있는 글자를 포함한 도식을 무조건 축소하지 않는다. `.mechanism`처럼 가로 관계를 세로 흐름으로 바꿀 수 있다.
- SVG의 `viewBox`는 그림의 크기를 정한다. 라벨의 실제 렌더링 크기도 확인한다.
- 캡션은 줄바꿈을 허용한다. 그림 번호와 설명이 따로 떨어지지 않게 한다.
- 실제 데이터가 없는 지표·개선율·스파크라인은 추가하지 않는다. 가상의 예시는 가상이라고 표시하며, 측정 결과처럼 쓰지 않는다.

애니메이션의 실행·취소·정적 모드 계약은 [인터랙션 레퍼런스](interactive-patterns.md)를 따른다.
